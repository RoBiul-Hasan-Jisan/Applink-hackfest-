# Data privacy
**Collected:** report type, area, optional landmark, optional location, optional photo, source, timestamps; reporter phone as keyed HMAC hash + last 4 digits; the number itself only **AES-256-GCM encrypted** and only if the resident consented to SMS updates; volunteer/staff profile + verified phone. **Not collected:** clinical or medical information.
**Photos:** consent required; JPEG/PNG only, <= 5 MB; EXIF/GPS/XMP/comments stripped in code before storage; stored in a private directory (never served statically), SHA-256 recorded, accessible only to staff and the assigned volunteer.
**Location:** optional; no precise resident location is displayed publicly; the area map shows reviewed area-level counts only.
**Consent and opt-out:** SMS updates are opt-in; `STOP` withdraws consent and deletes the stored contact number; campaigns reach only opted-in contacts, never twice in 24h.
**Access:** role-based via Firebase claims; staff see masked reporter ids only; messages are shown with pseudonymous references; OTP values are never stored or logged; logs never contain full phone numbers.
**Retention (implemented, tested):** a daily job deletes the encrypted contact number and SMS consent of *finished* reports (VERIFIED/REJECTED) `REPORTER_CONTACT_RETENTION_DAYS` (default 30) after their last change; open reports keep theirs. The keyed hash is kept (it enforces the daily limit and ownership) and is pseudonymous. Not yet automated: retention for photos, audit logs and the hash itself: decide and document those with the pilot site.
**Erasure (implemented, tested):** a resident can text `ERASE` (or `DELETE MY DATA`), or an admin can call `POST /api/admin/erase`. This deletes their contact number, last-4, ownership hash (replaced by a random token), resident-submitted photo files (checksum record kept, marked deleted) and message history; reports remain as anonymous records and still count in analytics. Staff/volunteer numbers cannot be erased this way. The audit log records only counts.
